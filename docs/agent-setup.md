# Agent setup guide

> How to take a fresh clone of this repository and restore everything a
> development agent needs. The repo itself is self-contained for Rust-side
> work; the numerical-parity harness needs two things that are intentionally
> not committed (`HANDOFF.md` and `refs/bullet3`). Companion to `README.md`
> (library usage) — this document covers the *development environment*.

## 0. Reading order (entry documents)

1. **`HANDOFF.md`** — the agent handoff document. It is **not in the repo**
   (gitignored on purpose: "local agent handoff notes"). Obtain it from the
   maintainer / the previous agent session. It carries the current state
   snapshot, confirmed decisions, the next-step agenda, and §6, a long
   do-not-repeat pitfall list. Everything below assumes you have it.
2. `docs/audit/00-project-status.md` — the in-repo source of truth (HEAD,
   project phase, roadmap, risks, Out of Scope).
3. `docs/bullet-deviations.md` — every intentional deviation from upstream
   Bullet. Read before "fixing" anything that looks wrong.
4. `docs/api-priorities.md` / `docs/api-gaps.md` — remaining API-surface work
   and implementation notes for what already shipped.
5. `docs/bullet-compare.md` (parity ledger), `docs/perf/speed.md` +
   `docs/perf/memory.md` (perf ledgers) — the regression baselines.

## 2. Tier 1 — Rust-side development (no extra setup)

Requirements: **Rust** (no toolchain pin committed; the project is validated
on `rustc 1.99.0-nightly (0e29c21d9 2026-07-21)` — match it when in doubt),
**Python 3** (tools), **Git**.

On Windows, Git-for-Windows ships a `/usr/bin/link.exe` (GNU coreutils) that can
shadow the MSVC linker and break linking. `.cargo/config.toml` is host-specific
and therefore **not committed** — create it yourself if cargo fails to link:

```toml
[target.x86_64-pc-windows-msvc]
linker = "rust-lld"
```

Keep that file untracked; it stays local.

Verification loop (all of it is expected green at every handoff):

```bash
cargo test --workspace                                   # f32 (default)
cargo test --workspace --features f64                    # f64
cargo clippy --workspace --all-targets                   # must be clean
cargo clippy --workspace --all-targets --features f64    # f64-only lints exist
python tools/check.py                                    # tests + 14 demo assertions
cargo check -p bullet-physics --no-default-features --features libm,f32   # no_std
cargo check -p bullet-physics --no-default-features --features libm,f64   # no_std
```

Toolchain notes:

- clippy runs **both** precisions (f64-only lints get missed otherwise);
  `approx_constant` is deny-level (use `core::f32::consts` / `bullet_math`
  constants, never `3.14`-style literals).
- Do **not** run `cargo fmt --all` — the repo is not rustfmt-clean and it
  would rewrite everything. New files may be normalized with
  `rustfmt --edition 2024 <file>` alone.
- `cargo test` accepts only one filter argument; run multiple targets one
  filter at a time.

## 3. Tier 2 — parity/perf harness against the real Bullet library

This is how every behavioral claim in the ledgers was produced. Windows +
MSVC + CMake required.

Requirements: **CMake** (validated 3.31), **Visual Studio 2022** (MSVC; the
community edition layout is what the scripts were written against), Git,
Python 3.

1. Clone the reference implementation into `refs/bullet3/` (gitignored) and
   pin it — **the exact commit matters**: the parity ledger is bit-level
   against this build, and a different Bullet version can shift classified
   rows.

   ```bash
   git clone https://github.com/bulletphysics/bullet3 refs/bullet3
   git -C refs/bullet3 checkout 63c4d67   # 3.27 line, the pinned reference
   ```

2. The first parity run builds the static Bullet libs automatically
   (one-time, slow): `target/bullet3-build` (f32) and
   `target/bullet3-build-double` (f64: `BT_USE_DOUBLE_PRECISION`,
   `/MT` runtime — see `ensure_bullet_libs` in `tools/parity.py`).

   ```bash
   python tools/parity.py --scene falling_box --precision f64
   ```

3. **MSVC environment**: `tools/build_recorder.py` hardcodes
   `VCVARS = r"D:\Microsoft Visual Studio\2022\Community\VC\Auxiliary\Build\vcvars64.bat"`.
   Every C++ probe builder imports `msvc_env()` from it — if your Visual
   Studio lives elsewhere, edit that one line.

4. Rebuild the recorder/probe exes as needed (they are gitignored):

   ```bash
   python tools/build_recorder.py                 # f32 only
   python -c "import build_recorder; build_recorder.build('f64')"
   python tools/build_multibody_probe.py [f32|f64|both]
   python tools/build_softbody_probe.py
   ```

5. Day-to-day commands:

   ```bash
   python tools/parity.py --scene X [--precision f32|f64] [--update-ledger]
   python tools/perf.py --scene all --stages        # speed ledger
   python tools/perf.py --scene all --mem           # memory ledger
   python tools/mbdiff.py --strip-trailing-cr a.txt b.txt
   ```

Notes: `cargo flamegraph` needs an admin shell on Windows, and after any
profiling session you must rebuild with standard flags (the `RUSTFLAGS`
artifact pollutes `target/release` — byte-level comparisons become fake).
Quick perf runs (`--repeats 1`) are far too noisy for attribution.

## 4. Optional — wasm browser demo

```bash
rustup target add wasm32-unknown-unknown
python tools/wasm-demo/build.py     # wasm + single-file HTML; dist/ gitignored
```

`tools/wasm-demo` is a workspace member but cfg-gated to wasm; it is never
built for the host.

## 5. Pitfall highlights (full list: `HANDOFF.md` §6)

- **Never batch-edit source files with scripts** — edit per file. Scripted
  replacements have corrupted files here more than once; verify with
  `git diff` after any bulk operation.
- Sandboxed shells: `git checkout -- <path>` may be blocked (use
  `git show HEAD:<path> > <path>`); commit messages containing backticks get
  command-substituted away (write `target/commit_msg.txt` + `git commit -F`,
  then delete it).
- MSVC prints NaN as `-nan(ind)`, which crashes `mbdiff.py` — grep both
  sides for NaN before diffing.
- The parity ledger has separate f32/f64 sections with different digits —
  always confirm which precision section you are comparing against.
- Chaos-prone scenes are pinned as "first N frames exact + long-term
  qualitative"; do not tighten ledger assertions without a root cause.
