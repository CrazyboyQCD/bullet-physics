# Performance ledger — Rust vs Bullet wall-clock comparison

Perf harness ledger for the "performance parity with upstream Bullet" goal
(the numeric sections are auto-generated by `tools/perf.py --update-ledger`;
the analysis text below each report is hand-written).

## Methodology

- **Runners.** `tools/bullet_perf.exe` (C++, `tools/bullet_perf.cpp`) and
  `cargo run --release -p bullet --example perf_scenes` consume the same
  generated scene tables (`tools/perf_scenes.json` ->
  `tools/generate_perf_scenes.py` -> `bullet_perf_scenes.h` +
  `src/perf_scenes_table.rs`), mirroring the parity harness's single-source
  discipline.
- **Protocol.** Per scene: build, run `warmup` untimed frames, then time
  `frames` fixed steps (`stepSimulation(dt, 1, dt)` / `step_simulation(dt)`),
  fresh world per repeat. `tools/perf.py --scene X --repeats 5` takes the
  median. `last300_ms` isolates the last 300 frames (the settled/sleeping
  steady state on long scenes).
- **Fairness.**
  - Both sides build in their default release configuration: MSVC `/O2` for
    the C++ runner (Bullet libs are the `target/bullet3-build` Release
    statics), `cargo --release` for Rust (the workspace profile adds fat LTO
    + `codegen-units = 1`; measured ~0 vs the default profile, so the
    comparison is unaffected). No arch-specific flags on either side.
  - The C++ broad phase follows the scene spec (same algorithm on both
    sides): `btAxisSweep3` for the sweep scenes — the same 3-axis
    sweep-and-prune as this crate's `AxisSweep3`, scoped with the scene's
    `broadphase_aabb` hint — or `btDbvtBroadphase` (Bullet's default) for
    the `dbvt_*` scenes, matching this crate's `DbvtBroadPhase`.
  - `SOLVER_RANDMIZE_ORDER` cleared, solver iterations from the scene spec —
    same reproducibility preconditions as the parity recorder.
  - Multibody scenes attach `btMultiBodyLinkCollider` spheres registered in
    the `DefaultFilter` group (island-solver precondition) and run a manual
    `forwardKinematics` before attaching; the Rust side attaches the same
    colliders and runs FK inside the step.
  - f32 only: performance targets the default precision.
  - **2026-08-28 clang-cl cross-check** (one-off, `target/build_clang_perf.py`,
    output `tools/bullet_perf_clang.exe`; the MSVC libs stay the ledger
    baseline — the de-facto Windows toolchain): rebuilding the whole Bullet
    stack with clang-cl 21 (`/O2 /MT`, same flags) speeds Bullet up by
    mb_chains −27% / rain_500 −20% / dbvt_rain_2000 −15% / stack_1000 −8%.
    Against the clang build the rust ratios become stack_1000 0.76x,
    rain_500 0.53x, dbvt_rain_2000 0.44x (still faster, 1.3-2.3x margin)
    and mb_chains 0.98x — that scene's edge was mostly the compiler gap,
    the other three are implementation wins.
- **Stage breakdown** is Rust-only (`--stages`): `PhysicsWorld::
  enable_step_timing` accumulates per-stage wall-clock inside
  `step_simulation` (7 stages mirroring Bullet's `BT_PROFILE` points); the
  C++ side has no equivalent hook without patching upstream sources.
  Timed runs never enable stage sampling, so the headline numbers stay
  unpolluted.
- **Caveats.** Absolute numbers are machine- and load-sensitive; only the
  rust/bullet ratio (same machine, interleaved runs) is meaningful. Chaotic
  trajectories may diverge slightly between engines, shifting when stacks
  settle or sleep — the body/contact counts stay comparable, so per-frame
  costs remain representative.

## Scenes

Scenes live in `tools/perf_scenes.json` (parameterized generators, never
hand-listed bodies): `stack_1000` (solver + sleeping steady state),
`rain_500` (narrow phase + broad phase over a height mesh), `mb_chains`
(Featherstone ABA + multibody solver), `dbvt_rain_2000` (large-scale rain
where both sides run their dynamic-BVH broad phase), `gimpact_rain_100`
(dynamic concave meshes: every pair runs the mesh-mesh path), and
`game_arena` (sustained game-style activity: launcher stream + driven
bulldozer via the per-scene `script` field).

Usage:

```bash
python tools/perf.py --scene all --stages --update-ledger
```

**Manifold-merge round (2026-09-01)**: the ratio moves 0.61x -> 0.91x.
The merge makes resting stacks accumulate the full four-point corner
manifold (like Bullet's) instead of the old single flipping point, so the
contact-row count per stack interface roughly quadruples and the solve cost
rises with it; the resurrected warm start (the refresh path carried a dead
0x0.85 before) only partly offsets it. This is the honest cost of the
correct behavior: stock Bullet pays the same four-point rows. Revisit after
rayon parallel island solve, which attacks the solve share directly.

**Allocation/branch-trimming round (2026-09-02)**: three
flamegraph-driven mechanical rewrites, each output-identical to the digit
(all six parity scenes f32/f64 byte-identical ledgers): (1)
`solve_contact` now takes its two-body split once per row per iteration
instead of three times (the normal/tangent blocks re-split through
`two_bodies`, ~2 assert+bounds-check pairs per row per iteration); (2) the
box-box Sutherland-Hodgman face clip and `cull_points` run on fixed stack
buffers (`ClipPoly`, cap 8) instead of ~8 heap `Vec` allocations per
face-face pair; (3) the island pass reuses pooled union-find + awake-flag
buffers (five per-step allocations -> zero steady-state). Rust-side total
moves 792.4 -> 753.7 ms (within session noise; the solve share stays 47.8%
and the islands stage lands at 5.3%) — the wins are individually at or
below the run-to-run noise floor, but the removed allocations are
certainty-level (no allocator jitter on the box-box hot path) and the
solve split structure is now rayon-ready. The ratio reads 0.91x -> 0.96x
against a Bullet side that swung 737-891 ms across this session's runs;
the rust side stayed inside 740-797 ms all day.

**Consumer-API round (2026-09-02)**: five S-tier consumer features
(all-hits rays, ray filter masks, per-body gravity, the custom pair
filter, CCD swept-bounds pruning) landed with no step-path cost by
construction — the ray APIs are queries outside the step, the per-body
gravity default equals the world value (same arithmetic), and the pair
filter is a `None`-checked gate on the pair pass. The CCD pruning
replaces each fast-mover's per-target exact cast with an AABB overlap
pretest, but no perf scene sets a CCD motion threshold, so it is a
zero-effect change on this ledger. Ratios moved within session noise
everywhere (stack_1000 0.96x -> 0.95x, game_arena 0.39x -> 0.37x,
softbody_mesh 0.40x -> 0.31x); all six parity scenes stayed
ledger-identical to the digit.

**2026-08-28 SipHash removal round (Fx-hash pair-keyed maps).** The
post-pair-set stack_1000 profile put the `manifold_cache` lookups at
~12.6% inclusive (`find_inner` + SipHash `hash_one` ~9% self): the map is
queried per broad-phase pair (mark/refresh/seed/entry/remove) plus once
per contact-point row in the impulse writeback — ~24k lookups per step on
the 1000-body stack. Both pair-keyed containers in `PhysicsWorld`
(`manifold_cache`, `no_collision_pairs`) now build with the same
FxHash-style multiply-rotate hasher the sweep pair cache used before it
became a sorted Vec (rustc's `FxHashMap` recipe; the keys are our own
`(usize, usize)` pairs, so SipHash's collision-resistance buys nothing).
The hash only picks the bucket and every consumer keys its access:
all six parity scenes' rust CSVs (f32/f64) and all 48 multibody probe
outputs are byte-identical. Measured: stack_1000 0.86x -> **0.68-0.75x**
(rust total 755 -> ~574 ms, narrowphase stage 234 -> 203 ms — the
lookups bill into the narrow-phase stage; Bullet-side variance moves the
ratio), rain_500 0.44x (rust 512 -> 476 ms, narrowphase 220 -> 172 ms),
mb_chains ~0.7x (unchanged, few pairs). Combined with the morning's
sorted pair set, stack_1000 is now at 0.96x -> ~0.7x on the day.

**2026-08-28 broadphase pair-set round (sorted pair set).** A fresh
stack_1000 flamegraph showed `compute_pairs` rebuilding its output every
frame: an Fx-hash `HashSet` walk + filter-collect (~7%) plus a full
`sort_unstable` (11.7%) — on a resting stack the pair set never changes
but was still collected and re-sorted every step. The pair cache is now a
`Vec` kept sorted lexicographically at all times (binary-search
insert/remove on the handful of pairs each edge swap touches), so
`compute_pairs` is a single ordered walk with the exact-AABB filter and no
sort; the `FxHasher` went away with the set it served. Rebuilds keep the
per-pair binary inserts (a bulk-load flag would leave `pair_remove`'s
binary search on an unsorted slice during `insert_handle`'s max-edge
bubbling; rebuild cost stays in the same order as the full edge re-quant
it already does). Output neutrality: same set, same order — the five
matches-brute-force tests, all six parity scenes' rust CSVs (f32/f64) and
all 48 multibody probe outputs are byte-identical. Measured: stack_1000
0.96x -> **0.86x** (broadphase stage 161.2 -> 88.6 ms; flamegraph repeats
770 -> ~680 ms; `quicksort` vanished from the profile), rain_500 0.47x
(broadphase 12.7 -> 4.5 ms, within session variance), mb_chains 0.69x.
The refreshed stack_1000 profile now reads: solve 38.7% (top),
`manifold_cache` SipHash lookups ~12.6% inclusive (`find_inner`), collide
13.4%, set_aabb 8.1% — and rain_500 surfaced a 5.7% `rebuild` share
(falling bodies keep outgrowing the auto-grown quantization frame; a
cheaper growth policy is output-neutral since the exact filter bounds the
reported set).

**2026-08-27 margin-core round (Bullet's margin architecture, commit
bab52e2).** The structural gap closed: GJK/EPA now walk the shapes'
shrunk cores (`core_support_local`/`world`: sphere -> point, capsule ->
segment, box/cylinder/cone -> componentwise -0.04; hulls/mesh triangles
stay margin 0) and add the margins back at the walk's exit — resting
pairs have separated cores, so the cheap distance walk resolves them
(exactly, a ball-Minkowski property) and EPA only runs for overlap past
the margin shell. This came with Bullet's `inSimplex` gate (a duplicated
support ends the walk — without it a sphere's point core against a flat
triangle hull cycles on duplicated supports until the iteration cap),
the signed band distance (negative = walk-resolved overlap), and a
closure-generic `enclosing_walk` shared by the full-shape intersect and
the core-based EPA fallback. Measured on rain_500: narrowphase
1067 -> ~220-240 ms (-79%), total ratio 1.22x -> **0.44x** (first time
faster than Bullet on this scene, 2.3x margin); solve is now the top
stage (44%). stack_1000 (SAT boxes + box-vs-triangle) 0.96x,
mb_chains 0.70x. Parity: all scenes bit-identical except the mesh box
row (walk-resolved box-vs-triangle contacts: bigger impact-frame peak,
tighter settling tail). Earlier that day: the analytic
sphere-triangle fast path (2eda695, -8% narrowphase) and the Vec3A
migration (bbc1ba4).

**2026-08-26 persistent-manifold round 2 (per-pair manifold cache + row
pool).** Contacts cached per broad-phase pair (anchors in both local
frames, `refreshContactPoints`-equivalent re-projection, impulse
inheritance, GJK seeded with the cached normal on re-detection); solver
rows/predicted poses pooled across steps. rain_500 went 2.81x → 2.09x
(narrowphase 2567 → 1967 ms) — the rolling/sliding majority of pairs
became refresh-served. Also that round: box_box face contacts report

**2026-08-26 margin-band round (contact detection + EPA pooling).**
Contacts now form while surfaces are still separated (the Bullet
`m_maximumDistanceSquared` route): the GJK distance walk reports band
contacts with negative penetration inside the per-pair breaking
threshold, broad-phase AABBs are padded by the global 0.02 contact
threshold (Bullet's `updateSingleAabb`), and the solver adds Bullet's
separation-rate softening for separated points. Two walk mechanics keep
far pairs cheap: Bullet's early rejection
(`delta^2 > |v|^2 * maxDist^2` proves separation beyond the band on the
first or second support query) and the overlap path feeds EPA directly
from the walk's enclosing tetrahedron (no second GJK run). EPA's
scratch buffers (vertex/face vectors and the per-expand boundary set)
are pooled per thread — the `Vec<Face>` churn the flamegraph called
out. Measured on rain_500: narrowphase 1967 → 1906 ms with the band
semantics active (intermediate states measured 3012 ms without the
early rejection and 2298 ms without the EPA pooling), ratio 2.09x →
2.27x against a Bullet side that itself ran ~6% faster this session
(1042 vs 1115 ms total). The band's residual cost is physics, not
waste: damped band oscillation around the surface keeps
shallow-penetration frames (and their EPA calls) in the settle phase
that a penetration-only detector resolves in one bounce — Bullet pays
the same dynamics. Parity held: box/mesh/stacking scenes are unchanged
to the digit, the plane-path impact transient grew (one earlier contact
frame at ~9 m/s, classified), and all 24 multibody probes keep their
first-divergence frames. stack_1000 reads 1.24x this session (vs 1.02x
previously) — mostly Bullet-side variance (its total dropped 797 → 689
ms; the sleeping steady state still favors Rust, last300 0.94x), with
a real +52 ms narrowphase cost from the inflated-AABB neighbor pairs
during the settle phase.

**2026-08-27 EPA boundary + sweep-pair hashing round.** A fresh
`cargo flamegraph` attributed the rain_500 step: EPA 50.8% (of which
`Vec<Face>::retain` 25.7% — almost entirely the boundary `HashSet`'s
SipHash on `(usize, usize)` keys — visibility scan 23.2%, edge/face
distance ~21% intrinsic), GJK 24.2%, solver 24.2%. Two structural
costs removed: the EPA horizon is now tracked in a pooled `Vec` with
linear reverse-edge matching (the horizon is tens of edges; face
creation order was already arbitrary under `RandomState` drain, so a
deterministic order changes nothing observable), and the axis-sweep
pair cache is keyed with an FxHash-style multiply-rotate hasher
instead of `RandomState`. Output neutrality proven hard: all 24
multibody probes × f32/f64 byte-identical against a `42d0ad8` worktree
baseline, and the six parity scenes keep their documented deviations
digit-for-digit. rain_500: narrowphase 1906 → 1491 ms (-22%), ratio
2.27x → 1.73x (Bullet side 1074 ms this session, ~3% slower than the
1042 ms reference — the narrowphase delta is real either way).
stack_1000 1.25x (last300 0.91x, the sleeping steady state favors
Rust), mb_chains 0.81x. The remaining EPA profile is intrinsic math
(edge/face distances, visibility dots); the next lever, if needed, is
Bullet's face-pool + adjacency-flood horizon layout (fixed-capacity
arrays, flood instead of full scans) — that changes iteration order
and needs full parity re-verification.

**2026-08-28 scene scaled 20 -> 200 chains + two waste fixes.** The
original 5x4/20-chain grid ran ~45us/frame — too small to separate engine
cost from launch noise (against clang-Bullet it read 0.98x, apparently
"on par"). Scaled to a 20x10 grid of 200 chains, the true gap surfaced:
rust 310 ms vs msvc 235 / clang 254 (1.22x vs clang) — a flamegraph put
**update_aabbs at 72%**, none of it physics:

1. `register_pending_colliders` ran its wanted-list rebuild + quadratic
d   duplicate scan **every step** (an 800-collider scene pays ~320k
   comparisons per frame; Bullet registers colliders once via
   `addCollisionObject`). Fixed with an O(n) attached-collider count
   fast path — colliders are only ever attached, so an unchanged count
   means nothing to register.
2. The auto-grown AxisSweep3 quantization frame kept 50% headroom; the
   chains' swinging AABB peaks drifted out of it, triggering full
   rebuilds, and the tight y frame quantized ~2x finer than the C++
   hint, doubling y-edge swap traffic. Headroom is now 100%, which both
   keeps oscillating bodies in-frame and coarsens quantization. Both
   effects are output-neutral (conservative floor/ceil quantization;
   `compute_pairs` reports the exact-filtered ordered pair set).

Verified output-neutral: all 12 parity ledger sections digit-identical,
all 24 multibody probes x f32/f64 byte-identical against the pre-fix
build, tests + clippy clean on both features. Measured: mb_chains 310 ->
273 ms (-12%, update_aabbs 225.6 -> 186.5 ms), rain_500 476 -> 454 ms
(update_aabbs 54.7 -> 41.5 ms), stack_1000 0.74x, dbvt_rain_2000 0.38x.
The remaining 67% update_aabbs share is the edge-swap storm itself —
800 heavily-overlapping swinging AABBs walked incrementally through the
edge tables, super-linear in scene density (10x bodies -> ~58x swaps at
the old headroom). That constant-factor gap vs Bullet's `updateHandle`
(plus the ordered-Vec pair cache vs Bullet's hash) is the next lever;
the articulated path itself (ABA + mb solve + transforms, ~86 ms) is
already faster than Bullet's whole 254 ms step.

**2026-08-28 edge-swap relayout (the constant-factor round, scene stays
on AxisSweep3 on both sides).** The remaining gap was pure per-swap
machinery: our `Edge` was 16 bytes (`u16 pos` + `usize` handle) vs
Bullet's 4, the per-proxy edge indices lived inside
`Vec<Option<Handle>>` (an `Option` unwrap + a fat bounds-checked write
per swap step), and both swap participants re-derived their handles from
the edge table every step. The relayout keeps the algorithm and every
sort/pair decision identical: `Edge` is 8 bytes (`u32` handle),
`min_edges`/`max_edges` are flat `Vec<[u32; 3]>` parallel arrays written
directly, and each `sort_*` bubble hoists the moving edge out of the
loop (its position/handle are invariants) so its own index is written
once at the end — only the displaced neighbour pays a per-step fixup.
Measured: mb_chains update_aabbs 186.5 -> **76.7 ms** (-59%), total 273
-> ~190 ms -> **0.68x** (vs clang-Bullet ~0.69x, first lead on this
scene); rain_500 update_aabbs 41.5 -> 30.5 ms (0.43x), stack_1000
0.64x, dbvt_rain_2000 0.37x. Output neutrality: the 141-test collision
suite (brute-force pair-for-pair included), all 12 parity ledger
sections and all 24 multibody probes x f32/f64 are digit/byte-identical
against the pre-relayout build.

**2026-08-28 mb solve allocation round (slice borrows + sweep scratch).**
The remaining mb-path allocations were all avoidable copies:
`calc_acceleration_deltas`/`apply_delta_vee`/`fill_row` already take
`&[Real]`, but every call site `to_vec()`-copied its jacobian / unit-

world.rs — split field borrows of `SolverData` or cross-object borrows

snapshot lives in a caller-owned `mb_row_scratch` reused across

total 163 -> ~154 ms (**0.67x** vs msvc / ~0.60x vs clang; rain_500
0.40x, stack 0.72x, dbvt_rain_2000 0.35x this session). Any simulation
with multibody contact or mb<->rb constraints benefits (ragdolls,
joint chains, articulated vehicles); pure rigid scenes are untouched.
Output neutrality: tests x both features, 12 parity sections and 24
multibody probes x f32/f64 digit/byte-identical against the pre-round
build.
