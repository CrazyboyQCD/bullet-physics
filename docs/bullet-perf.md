# Performance ledger — Rust vs Bullet wall-clock comparison

Perf harness ledger for the "performance parity with upstream Bullet" goal
(the numeric sections are auto-generated by `tools/perf.py --update-ledger`;
the analysis text below each report is hand-written).

## Methodology

- **Runners.** `tools/bullet_perf.exe` (C++, `tools/bullet_perf.cpp`) and
  `cargo run --release -p bullet --example perf_scenes` consume the same
  generated scene tables (`tools/perf_scenes.json` ->
  `tools/generate_perf_scenes.py` -> `bullet_perf_scenes.h` +
  `src/perf_scenes_table.rs`), mirroring the parity harness's single-source
  discipline.
- **Protocol.** Per scene: build, run `warmup` untimed frames, then time
  `frames` fixed steps (`stepSimulation(dt, 1, dt)` / `step_simulation(dt)`),
  fresh world per repeat. `tools/perf.py --scene X --repeats 5` takes the
  median. `last300_ms` isolates the last 300 frames (the settled/sleeping
  steady state on long scenes).
- **Fairness.**
  - Both sides build in their default release configuration: MSVC `/O2` for
    the C++ runner (Bullet libs are the `target/bullet3-build` Release
    statics), `cargo --release` for Rust. No arch-specific flags on either
    side.
  - The C++ broad phase is `btAxisSweep3` — the same 3-axis
    sweep-and-prune algorithm as this crate's `AxisSweep3` (the default
    `btDbvtBroadphase` would compare a different algorithm), scoped with the
    scene's `broadphase_aabb` hint.
  - `SOLVER_RANDMIZE_ORDER` cleared, solver iterations from the scene spec —
    same reproducibility preconditions as the parity recorder.
  - Multibody scenes attach `btMultiBodyLinkCollider` spheres registered in
    the `DefaultFilter` group (island-solver precondition) and run a manual
    `forwardKinematics` before attaching; the Rust side attaches the same
    colliders and runs FK inside the step.
  - f32 only: performance targets the default precision.
- **Stage breakdown** is Rust-only (`--stages`): `PhysicsWorld::
  enable_step_timing` accumulates per-stage wall-clock inside
  `step_simulation` (7 stages mirroring Bullet's `BT_PROFILE` points); the
  C++ side has no equivalent hook without patching upstream sources.
  Timed runs never enable stage sampling, so the headline numbers stay
  unpolluted.
- **Caveats.** Absolute numbers are machine- and load-sensitive; only the
  rust/bullet ratio (same machine, interleaved runs) is meaningful. Chaotic
  trajectories may diverge slightly between engines, shifting when stacks
  settle or sleep — the body/contact counts stay comparable, so per-frame
  costs remain representative.

## Scenes

Scenes live in `tools/perf_scenes.json` (parameterized generators, never
hand-listed bodies): `stack_1000` (solver + sleeping steady state),
`rain_500` (narrow phase + broad phase over a height mesh), `mb_chains`
(Featherstone ABA + multibody solver).

Usage:

```bash
python tools/perf.py --scene all --stages --update-ledger
```

**2026-08-28 broadphase pair-set round (sorted pair set).** A fresh
stack_1000 flamegraph showed `compute_pairs` rebuilding its output every
frame: an Fx-hash `HashSet` walk + filter-collect (~7%) plus a full
`sort_unstable` (11.7%) — on a resting stack the pair set never changes
but was still collected and re-sorted every step. The pair cache is now a
`Vec` kept sorted lexicographically at all times (binary-search
insert/remove on the handful of pairs each edge swap touches), so
`compute_pairs` is a single ordered walk with the exact-AABB filter and no
sort; the `FxHasher` went away with the set it served. Rebuilds keep the
per-pair binary inserts (a bulk-load flag would leave `pair_remove`'s
binary search on an unsorted slice during `insert_handle`'s max-edge
bubbling; rebuild cost stays in the same order as the full edge re-quant
it already does). Output neutrality: same set, same order — the five
matches-brute-force tests, all six parity scenes' rust CSVs (f32/f64) and
all 48 multibody probe outputs are byte-identical. Measured: stack_1000
0.96x -> **0.86x** (broadphase stage 161.2 -> 88.6 ms; flamegraph repeats
770 -> ~680 ms; `quicksort` vanished from the profile), rain_500 0.47x
(broadphase 12.7 -> 4.5 ms, within session variance), mb_chains 0.69x.
The refreshed stack_1000 profile now reads: solve 38.7% (top),
`manifold_cache` SipHash lookups ~12.6% inclusive (`find_inner`), collide
13.4%, set_aabb 8.1% — and rain_500 surfaced a 5.7% `rebuild` share
(falling bodies keep outgrowing the auto-grown quantization frame; a
cheaper growth policy is output-neutral since the exact filter bounds the
reported set).

**2026-08-27 margin-core round (Bullet's margin architecture, commit
bab52e2).** The structural gap closed: GJK/EPA now walk the shapes'
shrunk cores (`core_support_local`/`world`: sphere -> point, capsule ->
segment, box/cylinder/cone -> componentwise -0.04; hulls/mesh triangles
stay margin 0) and add the margins back at the walk's exit — resting
pairs have separated cores, so the cheap distance walk resolves them
(exactly, a ball-Minkowski property) and EPA only runs for overlap past
the margin shell. This came with Bullet's `inSimplex` gate (a duplicated
support ends the walk — without it a sphere's point core against a flat
triangle hull cycles on duplicated supports until the iteration cap),
the signed band distance (negative = walk-resolved overlap), and a
closure-generic `enclosing_walk` shared by the full-shape intersect and
the core-based EPA fallback. Measured on rain_500: narrowphase
1067 -> ~220-240 ms (-79%), total ratio 1.22x -> **0.44x** (first time
faster than Bullet on this scene, 2.3x margin); solve is now the top
stage (44%). stack_1000 (SAT boxes + box-vs-triangle) 0.96x,
mb_chains 0.70x. Parity: all scenes bit-identical except the mesh box
row (walk-resolved box-vs-triangle contacts: bigger impact-frame peak,
tighter settling tail). Earlier that day: the analytic
sphere-triangle fast path (2eda695, -8% narrowphase) and the Vec3A
migration (bbc1ba4).

**2026-08-26 persistent-manifold round 2 (per-pair manifold cache + row
pool).** Contacts cached per broad-phase pair (anchors in both local
frames, `refreshContactPoints`-equivalent re-projection, impulse
inheritance, GJK seeded with the cached normal on re-detection); solver
rows/predicted poses pooled across steps. rain_500 went 2.81x → 2.09x
(narrowphase 2567 → 1967 ms) — the rolling/sliding majority of pairs
became refresh-served. Also that round: box_box face contacts report
the witness on B uniformly. A `cargo flamegraph` attribution showed
`epa::penetration` at ~40–65% of the whole step (`Vec<Face>` churn:
retain ~22%, expand re-sort ~21%), everything else under a few percent
— pointing at margin-band detection as the next lever.

**2026-08-26 margin-band round (contact detection + EPA pooling).**
Contacts now form while surfaces are still separated (the Bullet
`m_maximumDistanceSquared` route): the GJK distance walk reports band
contacts with negative penetration inside the per-pair breaking
threshold, broad-phase AABBs are padded by the global 0.02 contact
threshold (Bullet's `updateSingleAabb`), and the solver adds Bullet's
separation-rate softening for separated points. Two walk mechanics keep
far pairs cheap: Bullet's early rejection
(`delta^2 > |v|^2 * maxDist^2` proves separation beyond the band on the
first or second support query) and the overlap path feeds EPA directly
from the walk's enclosing tetrahedron (no second GJK run). EPA's
scratch buffers (vertex/face vectors and the per-expand boundary set)
are pooled per thread — the `Vec<Face>` churn the flamegraph called
out. Measured on rain_500: narrowphase 1967 → 1906 ms with the band
semantics active (intermediate states measured 3012 ms without the
early rejection and 2298 ms without the EPA pooling), ratio 2.09x →
2.27x against a Bullet side that itself ran ~6% faster this session
(1042 vs 1115 ms total). The band's residual cost is physics, not
waste: damped band oscillation around the surface keeps
shallow-penetration frames (and their EPA calls) in the settle phase
that a penetration-only detector resolves in one bounce — Bullet pays
the same dynamics. Parity held: box/mesh/stacking scenes are unchanged
to the digit, the plane-path impact transient grew (one earlier contact
frame at ~9 m/s, classified), and all 24 multibody probes keep their
first-divergence frames. stack_1000 reads 1.24x this session (vs 1.02x
previously) — mostly Bullet-side variance (its total dropped 797 → 689
ms; the sleeping steady state still favors Rust, last300 0.94x), with
a real +52 ms narrowphase cost from the inflated-AABB neighbor pairs
during the settle phase.

**2026-08-27 EPA boundary + sweep-pair hashing round.** A fresh
`cargo flamegraph` attributed the rain_500 step: EPA 50.8% (of which
`Vec<Face>::retain` 25.7% — almost entirely the boundary `HashSet`'s
SipHash on `(usize, usize)` keys — visibility scan 23.2%, edge/face
distance ~21% intrinsic), GJK 24.2%, solver 24.2%. Two structural
costs removed: the EPA horizon is now tracked in a pooled `Vec` with
linear reverse-edge matching (the horizon is tens of edges; face
creation order was already arbitrary under `RandomState` drain, so a
deterministic order changes nothing observable), and the axis-sweep
pair cache is keyed with an FxHash-style multiply-rotate hasher
instead of `RandomState`. Output neutrality proven hard: all 24
multibody probes × f32/f64 byte-identical against a `42d0ad8` worktree
baseline, and the six parity scenes keep their documented deviations
digit-for-digit. rain_500: narrowphase 1906 → 1491 ms (-22%), ratio
2.27x → 1.73x (Bullet side 1074 ms this session, ~3% slower than the
1042 ms reference — the narrowphase delta is real either way).
stack_1000 1.25x (last300 0.91x, the sleeping steady state favors
Rust), mb_chains 0.81x. The remaining EPA profile is intrinsic math
(edge/face distances, visibility dots); the next lever, if needed, is
Bullet's face-pool + adjacency-flood horizon layout (fixed-capacity
arrays, flood instead of full scans) — that changes iteration order
and needs full parity re-verification.


**2026-08-27 face-pool prototype reverted; face-distance probing
streamlined.** The Bullet face-pool layout (m_fc_store + free list +
adjacency-linked hull, horizon edges collected through neighbor
lookups instead of reverse-edge matching) was implemented with the
removed-set kept identical to the compacting scan. Measured on
rain_500: narrowphase 1491 -> ~1785 ms (+20%) — the wider face
struct, live-list pointer chasing and the two-pass removal
classification cost more than the retained-scan compaction they
replaced. Reverted; the Vec-of-faces layout stands and the flood
variant (which would also change the removed set on non-connected
visible patches) is not worth its parity risk at this profile.
Kept: face_distance's Option::or_else closure chain became early
returns with #[inline] on both helpers (identical probe order and
numerics; the closure plumbing alone measured ~1.3% of the step).
rain_500 narrowphase 1491 -> ~1430 ms, ratio ~1.67x. All 24
multibody probes x f32/f64 remain byte-identical against 42d0ad8;
parity deviations digit-for-digit unchanged.
