# Performance ledger — Rust vs Bullet wall-clock comparison

Perf harness ledger for the "performance parity with upstream Bullet" goal
(the numeric sections are auto-generated by `tools/perf.py --update-ledger`;
the analysis text below each report is hand-written).

## Methodology

- **Runners.** `tools/bullet_perf.exe` (C++, `tools/bullet_perf.cpp`) and
  `cargo run --release -p bullet --example perf_scenes` consume the same
  generated scene tables (`tools/perf_scenes.json` ->
  `tools/generate_perf_scenes.py` -> `bullet_perf_scenes.h` +
  `src/perf_scenes_table.rs`), mirroring the parity harness's single-source
  discipline.
- **Protocol.** Per scene: build, run `warmup` untimed frames, then time
  `frames` fixed steps (`stepSimulation(dt, 1, dt)` / `step_simulation(dt)`),
  fresh world per repeat. `tools/perf.py --scene X --repeats 5` takes the
  median. `last300_ms` isolates the last 300 frames (the settled/sleeping
  steady state on long scenes).
- **Fairness.**
  - Both sides build in their default release configuration: MSVC `/O2` for
    the C++ runner (Bullet libs are the `target/bullet3-build` Release
    statics), `cargo --release` for Rust. No arch-specific flags on either
    side.
  - The C++ broad phase is `btAxisSweep3` — the same 3-axis
    sweep-and-prune algorithm as this crate's `AxisSweep3` (the default
    `btDbvtBroadphase` would compare a different algorithm), scoped with the
    scene's `broadphase_aabb` hint.
  - `SOLVER_RANDMIZE_ORDER` cleared, solver iterations from the scene spec —
    same reproducibility preconditions as the parity recorder.
  - Multibody scenes attach `btMultiBodyLinkCollider` spheres registered in
    the `DefaultFilter` group (island-solver precondition) and run a manual
    `forwardKinematics` before attaching; the Rust side attaches the same
    colliders and runs FK inside the step.
  - f32 only: performance targets the default precision.
- **Stage breakdown** is Rust-only (`--stages`): `PhysicsWorld::
  enable_step_timing` accumulates per-stage wall-clock inside
  `step_simulation` (7 stages mirroring Bullet's `BT_PROFILE` points); the
  C++ side has no equivalent hook without patching upstream sources.
  Timed runs never enable stage sampling, so the headline numbers stay
  unpolluted.
- **Caveats.** Absolute numbers are machine- and load-sensitive; only the
  rust/bullet ratio (same machine, interleaved runs) is meaningful. Chaotic
  trajectories may diverge slightly between engines, shifting when stacks
  settle or sleep — the body/contact counts stay comparable, so per-frame
  costs remain representative.

## Scenes

Scenes live in `tools/perf_scenes.json` (parameterized generators, never
hand-listed bodies): `stack_1000` (solver + sleeping steady state),
`rain_500` (narrow phase + broad phase over a height mesh), `mb_chains`
(Featherstone ABA + multibody solver).

Usage:

```bash
python tools/perf.py --scene all --stages --update-ledger
```
